GitHub + Markdown Quick Reference

My personal cheat sheet for building and maintaining this portfolio. Workflow: BUILD, DOCUMENT, SANITIZE, COMMIT, PUBLISH, VERIFY.

Key Terms

  • Repository: a project and the files associated with it. Mine is reyhrm/reyhrm.github.io.
  • Commit: a saved checkpoint of changes made to the repository.
  • README: a file that explains a repository or project, usually README.md.
  • GitHub Pages: publishes website content from a GitHub repository.
  • Public: anyone can potentially view the repository.
  • Private: access is restricted to approved users.

Good Commit Messages

A commit message should briefly explain what changed.

  • Add About page
  • Update cybersecurity skills
  • Document Linux hardening project

Fix It Before You Panic

  • Site not updating: Did I commit? Did the deployment finish? Am I on the correct URL?
  • 404 error: check the filename, capitalization, and link path.
  • Image missing: check the images folder and the exact src path.
  • Broken nav: confirm the target file exists and the spelling matches.

10-Second Security Check

Before every commit, ask:

  • Secrets or passwords?
  • Tokens or keys?
  • Personal information?
  • Challenge answers or flags?
  • Classmate information?

STOP, SANITIZE, COMMIT. If something should not be public, fix it before publishing it.
